# HUG-251 — Dockerize FastAPI backend (per-issue plan)

## Goal

Produce a Cloud Run-ready container image of `packages/api` that:
- Includes the workspace transitive runtime deps (api + nl-engine + synth-data) plus the `mf` CLI that `nl_engine.repo.metricflow` invokes at runtime.
- Excludes dev tooling (ruff, mypy, pytest, etc.).
- Runs as non-root on port 8080 with `uvicorn` as PID 1 so Cloud Run's SIGTERM lands cleanly.
- Stays under 600MB compressed.

## Decisions for this issue

### 1. Build context = repo root, Dockerfile lives at `packages/api/Dockerfile`

The original plan said "create `packages/api/.dockerignore`". But because the build needs access to all three workspace members (`packages/api`, `packages/nl-engine`, `packages/synth-data`), the build context has to be the repo root, not `packages/api`. Docker's `.dockerignore` lives next to the build context, so I'm putting it at the repo root, not inside `packages/api/`.

Build command becomes:
```
docker build -f packages/api/Dockerfile -t hughes-api:test .
```

### 2. New dep group `runtime-extras` for the `mf` CLI

`dbt-postgres` and `dbt-metricflow` are currently in `[dependency-groups].dev` in the repo-root `pyproject.toml`. But the API lifespan warmup at `packages/api/src/api/main.py:42` imports `nl_engine.repo.metricflow`, which in turn `subprocess.run`s `mf …` (see `packages/nl-engine/src/nl_engine/repo/metricflow.py:62`). Without `mf` on PATH, the warmup fails.

Adding a new `runtime-extras` group with just these two packages and pulling them in via `uv sync --no-dev --group runtime-extras --frozen` keeps the image lean while still providing the CLI. Leaving the `dev` entries intact for backward compat with local workflows.

### 3. Multi-stage build

- **Builder:** `python:3.12-slim` + uv 0.11.7 (pinned to local dev version). `uv sync --frozen --no-dev --group runtime-extras` produces `/app/.venv` with editable installs of the workspace members pointing at `/app/packages/*/src`.
- **Runtime:** `python:3.12-slim` + `libpq5` (psycopg native) + `ca-certificates` (TLS to `ollama.com`). Copies the venv + workspace dirs + `config/` + `packages/dbt-models/`. Non-root `hughes` user, UID 1000. Direct `exec` form CMD.

### 4. Editable installs across stages: paths must match

`uv sync` writes `.pth` files into the venv that point at absolute paths like `/app/packages/api/src`. If the runtime stage's paths differ, imports break. Keeping `/app/...` consistent between stages is required.

### 5. What's in vs out of the image

In:
- `/app/.venv` — resolved runtime deps + `mf` CLI
- `/app/packages/api`, `packages/nl-engine`, `packages/synth-data` (source the editable installs point at)
- `/app/config` (`llm.yaml` is read by `nl_engine.llm.factory` at first use)
- `/app/packages/dbt-models` (the dbt project the `mf` subprocess reads)

Out (via `.dockerignore`):
- All `__pycache__/`, `.venv/`, `.pytest_cache/`, `.mypy_cache/`, `.ruff_cache/`
- `tests/`, `eval_artifacts/`, `packages/dbt-models/target/`, `dbt_packages/`, `logs/`
- `packages/frontend/`, `node_modules/`
- `.git/`, `.env`, `*.log`, editor dirs
- `infra/`, `scripts/`, `docs/`, `.github/`, `docker-compose.yml`

### 6. CI build job

Add a job to `.github/workflows/ci.yml` that runs `docker build -f packages/api/Dockerfile .` on changes to:
- `packages/api/**`
- `packages/nl-engine/**`
- `packages/synth-data/**`
- `pyproject.toml`
- `uv.lock`
- `packages/api/Dockerfile`

Fails CI if build fails or image is >800MB (50% buffer above the 600MB acceptance target — gives some headroom before causing CI flakes).

## Test plan for this issue

1. `docker build -f packages/api/Dockerfile -t hughes-api:test .` succeeds.
2. `docker images hughes-api:test --format '{{.Size}}'` is <600MB.
3. `docker run --rm hughes-api:test id` shows non-root uid.
4. `docker run --rm hughes-api:test which mf` returns a path inside the venv (proves `runtime-extras` was installed).
5. **Cold-start fast path:** `docker run --rm -p 8080:8080 -e DATABASE_URL=... -e OLLAMA_API_KEY=... -e API_WARM_CATALOG=0 hughes-api:test` — `curl localhost:8080/health` returns 200 within 10s.
6. **Cold-start warmup path (slow, ~4min):** same but `API_WARM_CATALOG=1`. `/health` returns 200 within 6 min, logs show `catalog_warmup.start` and `catalog_warmup.done`.
7. **Graceful shutdown:** `docker stop` produces uvicorn shutdown logs, not SIGKILL after the 10s grace.

If test 5 fails I park and document. Tests 6 and 7 are best-effort — if they take too long or local Postgres isn't trivially reachable, I document the skip in the issue's completion comment.
