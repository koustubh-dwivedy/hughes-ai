# HUG-257 — Cost cap, runtime DB role test, deploy.sh, runbook (per-issue plan)

## Goal

Wrap the deployment with safety + DX scaffolding:
1. Pytest that re-asserts the runtime DB role's privilege model.
2. `make verify-prod-role` target for one-command verification.
3. `infra/deploy.sh` orchestrating `deploy-api.sh` + `deploy-frontend.sh` with pre-flight checks.
4. Major expansion of `infra/README.md` runbook.
5. Operator step for the Ollama Cloud spend cap (web UI, can't be scripted).

## Key decisions

### 1. The pytest file is `infra/tests/test_runtime_role.py`, not under `tests/`

This file connects to *prod* Cloud SQL via the Auth Proxy and re-asserts the runtime role's privileges. It's not a unit test (CI would need cloud creds to run it), so it lives outside `tests/` to keep the unit/integration suites unaffected. The `make verify-prod-role` target runs it explicitly when needed.

### 2. `deploy.sh` fails fast on dirty working tree (configurable)

By default, `deploy.sh` exits non-zero if `git status` is dirty. Override with `ALLOW_DIRTY=1 bash infra/deploy.sh` during iteration. This matches the policy in `deploy-api.sh` (which only warns); `deploy.sh` is the "I'm shipping this to prod" entry point, hence stricter.

### 3. Runbook is in `infra/README.md`, not a separate file

Keeps everything in one place; matches the repo convention (no per-script README).

### 4. Ollama Cloud spend cap is an operator step in the checklist

Ollama Cloud's billing dashboard is a web UI; there's no GCP-equivalent of setting a spend cap via gcloud. Document the click path; surface it in the post-run "Operator checklist" Linear issue.
