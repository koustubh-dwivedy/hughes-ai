# HUG-254 — Deploy API to Cloud Run (per-issue plan)

## Goal

Build the API image via Cloud Build (in `tryhughes`, `europe-west1`), push to Artifact Registry `hughes`, deploy a Cloud Run service `hughes-api` with always-warm scaling, IAM-locked invocation, secrets from Secret Manager, and the dedicated runtime SA from HUG-252.

## Key decisions for this issue

### 1. Cloud Build does the cross-arch image build

Local builds on Apple Silicon produce arm64 images; Cloud Run runs amd64. Rather than building amd64 locally via QEMU (slow), have Cloud Build do it natively in its amd64 runners. `gcloud builds submit` uploads the build context to Cloud Build, which builds remotely.

### 2. Tag images with git SHA + `latest`

Two tags per build:
- `:<git-sha>` — immutable, used for the Cloud Run revision (enables clean rollback via `gcloud run services update-traffic`).
- `:latest` — moving pointer, used by docs / convenience tooling.

If the working tree is dirty when deploy-api.sh runs, append `-dirty` to the SHA tag and a warning to stdout (don't block — useful during iteration, but the runbook tells operators to commit-first for prod).

### 3. `API_ROOT_PATH=/api` (env var → FastAPI's `root_path`)

Firebase Hosting's `run:` rewrite forwards `/api/threads` to Cloud Run as `/api/threads` (no prefix-strip). The FastAPI app today binds routes at `/threads`. Three options were considered (see HUG-255 plan); the chosen path is **env-var-driven**: `packages/api/src/api/main.py` reads `API_ROOT_PATH` and passes it to `FastAPI(root_path=...)`. Cloud Run sets it to `/api`; local dev leaves it unset.

This is in HUG-254 (rather than HUG-255) because:
- It's a single env-var addition to the deploy script.
- The actual main.py change is a one-line modification.
- Deferring it to HUG-255 would leave HUG-254's smoke test in an awkward "API works but frontend can't reach it" state.

### 4. Cloud Run settings

| Setting | Value | Why |
|---|---|---|
| `--min-instances` | `1` | Avoids the 4-min MetricFlow warmup cold start on every visitor. ~$15/mo. |
| `--max-instances` | `3` | Hard cost ceiling against abuse / scrapers. |
| `--memory` | `2Gi` | MetricFlow warmup loads ~210 deps; 1Gi was OOM in early testing on similar setups. |
| `--cpu` | `1` | Single vCPU is enough for this traffic shape. |
| `--timeout` | `300` (5 min) | Agent calls can be slow; longer than default 60s. |
| `--concurrency` | `40` | Conservative for an LLM-backed API. Tunable later. |
| `--no-allow-unauthenticated` | (set) | Lock to IAM invokers (Firebase Hosting only). |
| `--service-account` | `hughes-api-sa@tryhughes.iam.gserviceaccount.com` | Dedicated SA from HUG-252. |
| `--add-cloudsql-instances` | `tryhughes:europe-west1:hughes-pg` | Mounts Unix socket at `/cloudsql/<conn>`. |

### 5. Firebase Hosting → Cloud Run invoker permission

When Firebase Hosting proxies through to Cloud Run via `rewrites.run`, it uses the Firebase service identity to invoke. This identity is per-Firebase-project and needs `roles/run.invoker` on the Cloud Run service. Granted by `deploy-api.sh` after the service exists.

The Firebase service identity has the form `service-<project-number>@gcp-sa-firebasehosting.iam.gserviceaccount.com`. Specifically for `tryhughes` (project number 14067832725): `service-14067832725@gcp-sa-firebasehosting.iam.gserviceaccount.com`. The grant only needs to happen once but is idempotent so we re-apply on every deploy.

## Test plan

1. `bash infra/deploy-api.sh` completes within ~10 min (image build + Cloud Run deploy).
2. `gcloud run services describe hughes-api --region europe-west1 --project tryhughes` shows correct settings.
3. `TOKEN=$(gcloud auth print-identity-token)` then `curl -H "Authorization: Bearer $TOKEN" https://hughes-api-<hash>.run.app/api/health` → 200 (note: `/api/health`, not `/health`, because `API_ROOT_PATH=/api`).
4. Unauthenticated curl to the `*.run.app` URL → 403.
5. `gcloud run services logs read hughes-api --region europe-west1 --limit 50` shows the MetricFlow warmup completing.
6. Wait 30 min, repeat (3) — response time still <2s (warm).
